# AegisFlow interface design

## 1. Principles

1. **Safety semantics before aesthetics.** Amber means simulated; green means a recorded human approval; red means rejected or failed. Status is always icon + text, never color alone.
2. **One primary action per view.** Teal is reserved for the action the user should take next.
3. **Calm authority.** Deep ocean-navy rail, light slate canvas, soft card shadows. No pure black, no neon, no decorative animation.
4. **Accessible by default.** Visible focus, 44 px targets, 4.5:1 text contrast, reduced-motion support, skip link.
5. **Show the evidence.** Version, content hash, reviewer, and timestamps appear at the moment of decision.

## 2. Palette

| Token | Value | Use |
|---|---|---|
| `--ag-bg` | `#F9FAFC` / dark `#0B1220` | Page canvas |
| `--ag-surface` | `#FFFFFF` / dark `#111C2E` | Cards, inputs |
| `--ag-text` | `#0F172A` / dark `#E6EDF7` | Body text |
| `--ag-muted` | `#5B6B82` / dark `#A9B8CC` | Captions and metadata |
| `--ag-primary` | `#0E766D` | Primary action, selected state |
| `--ag-sidebar` | `#0C1F31` | Navigation rail base |
| sidebar gradient | `#0C2033 → #0A1A2B → #0B2831` with a teal corner glow | Rail depth |
| `--ag-warning` | `#B45309` / dark `#FCD34D` | SIMULATED, awaiting review |
| `--ag-success` | `#15803D` / dark `#86EFAC` | Recorded human approval only |
| `--ag-danger` | `#B91C1C` / dark `#FCA5A5` | Rejected, failed, destructive |

The rail is deliberately **not** pure black: it is a deep teal-navy gradient with a subtle radial highlight, so the product feels crafted without competing with the content.

## 3. Typography and spacing

- Headings: Plus Jakarta Sans, 600–700, tight tracking.
- Body: Inter, 15–16 px, 1.55 line height.
- Code and hashes: JetBrains Mono.
- Spacing follows an 8 px rhythm; cards use 12 px radius and a two-layer soft shadow.

## 4. Layout

| Width | Behaviour |
|---|---|
| ≥1200 px | Full rail, two-column workflow/review, four metric cards |
| 900–1199 px | Rail, stacked page columns, two metric cards per row |
| 768–899 px | Single-column content, rail visible |
| <768 px | Rail collapsed, single column, sticky decision panel, stacked metrics |

## 5. Components

- **Status badge** — icon + label, tokenized by status class.
- **Decision panel** — reviewer name, consequence text per option, version-named actions, acknowledgement and terminal confirmation.
- **History row** — task id, request, badge, decision, AI time, and one row action.
- **Cards** — white surface, subtle border, soft shadow; no nested card borders.
- **Skip link** — first focusable element, jumps to `#ag-main`.

## 6. Accessibility evidence

- axe-core 4.10.2, WCAG 2.1 A/AA, **0 violations** on Dashboard, New Task, Workflow, Review, and History in both light and dark mode.
- Theme tokens 16/16 PASS; contrast 40/40 PASS.
- Keyboard focus shows a 2 px teal outline; `prefers-reduced-motion` disables transitions.
- No horizontal overflow at 360/768/1280/1536 px.
- Generated by `scripts/check_accessibility.py` and `scripts/check_pages.py`; CI uploads screenshots and audit JSON as `ui-evidence`.

## 7. Safety invariants held by the UI

- Green appears only on approved/completed states that require a recorded approval.
- SIMULATED is amber, labelled, and repeated on Dashboard, Workflow, and Review.
- Approval is bound to the current version and hash and names the version in the button.
- Rejection and deletion require explicit confirmation.
- Drafts are read-only; editing creates a new version and fresh approval.

## 8. Known constraints

- Streamlit owns the DOM, so semantic landmarks are limited to what it emits; the skip link and labelled controls compensate.
- There is no in-app light/dark toggle; the palette follows the OS setting through `light-dark()`.
- Visual checks are screenshot- and axe-based; no pixel-diff against the original mockup PDF is performed.
