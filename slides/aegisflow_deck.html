The problem

One model call hides three risks

01 · INTEGRITY

Fabrication

The model adds a budget, deadline, or name that was never in the source.

02 · SECURITY

Prompt injection

A document tells the model to ignore instructions, reveal secrets, or skip review.

03 · GOVERNANCE

Unaccountable automation

Nobody can prove what was approved, by whom, or whether it changed afterward.

A prompt is advisory. A control has to be enforced in code — and a human has to own the final decision.

Give one concrete example for each risk. Then transition: prompt engineering alone cannot solve these problems.

Architecture

A real hierarchy — delegation down, escalation up

USER → PLANNER → ORCHESTRATOR ├─ Analysis Lead → Document Analyst → Evidence Verifier ├─ Drafting Lead → Report Writer └─ Assurance Lead → Policy Checker → Independent Reviewer → HUMAN APPROVAL → FINALIZE → EXPORT

Level 1 · Command

Planner first. Root Orchestrator routes deterministically and enforces limits.

Level 2 · Team leads

Rule-based supervisors. No extra model calls. Own prerequisites, retries, completion.

Level 3 · Workers

LLM agents do language work. Deterministic checks and humans own authority.

Work is delegated downward, results report upward, problems escalate to the human.

Team leads make zero model calls. This hybrid hierarchy is deliberate: permissions should not be arguable by a language model.

Persist first

The UI writes the decision to SQLite before Command(resume=...). A crash leaves a durable record, not a lost approval.

Then re-verify

The graph re-reads the persisted review for the exact version and hash. A forged resume payload cannot finalize a task.

Approve → finalize · Reject → terminal · Revise → bounded loop with a new version

Slow down here. Persist-first, resume-second is the core defense.

Approval is not a boolean flag; it is bound to version id + SHA-256.

Trust boundaries

Untrusted in. Grounded out.

Uploaded text is data

  • Wrapped in <untrusted_document> delimiters
  • Scanned for ignore / override / reveal patterns
  • Instruction-like sentences skipped
  • Zero action tools to hijack — no email, shell, browser
  • Human approval remains mandatory

Every claim is traceable

  • Filename + location for each extracted claim
  • Supported / unsupported / conflicting / unverified
  • Required Sources and Limitations sections
  • Deterministic policy check + independent reviewer
  • Human sees the evidence before approving
TC-06: injection text does not reach the draft; a clean deadline from the same file survives.

Call it defense-in-depth, not a guarantee. Regex detection is incomplete; the empty tool allowlist and human gate are backstops.

11 / 16

Human approval

Bound to the exact output

draft v1 + SHA-256 → human reads draft, claims, evidence, findings → decision persisted in SQLite (actor = human:*) → graph resume → re-read approval → re-check hash → finalize → export re-check → approved Markdown / TXT

New version?

The prior approval becomes stale. Only the current version can be reviewed.

Content changed?

Finalize and export refuse. The stored hash no longer matches.

Integrity detection, not a cryptographic signature. Local DB tampering is documented as residual risk.

Only human:* actors may write decisions. Agents never import the approval module.

The hash is not non-repudiation; be explicit about that.
